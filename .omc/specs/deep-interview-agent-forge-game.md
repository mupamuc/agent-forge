## Goal
Сделать браузерную обучающую игру **Agent Forge**, где игрок учится **собирать AI-агентов**, принимая те же решения, что инженер: под данную миссию подобрать **минимальный правильный набор деталей** (роль/инструкция, инструменты, память, планировщик, stopping criteria, guardrails), запустить агента, прочитать пошаговую **историю «что агент сделал»** и починить по диагнозу провала. Контент опирается на два корпуса: PDF «Agentic AI: A Complete Learning Guide» (концепции) и репозиторий `FlorianBruniaux/claude-code-ultimate-guide` (практика, банк 271 вопрос, прогрессия Beginner→Expert, 181 шаблон).

## Audience (UPDATED 2026-06-06)
**Целевая аудитория — НЕ айтишники:** менеджеры проектов, офисные сотрудники. Работают с Claude через web (claude.ai chat), НЕ через терминал/консоль. Следствия:
- На экране игрока **ноль кода/JSON/терминала**. Только карточки, кнопки, история по шагам как переписка.
- Язык **офисный**, не инженерный. Реальный тех-термин показывается опционально за «(?)»-тултипом (учим настоящему слову, но не пугаем).
- Вид UI = знакомая «настройка ассистента / чат», а не IDE/граф нод.
- Якорь к знакомому: «это как настроить Проект в Claude.ai и дать ему файлы/интернет».
- Каждый провал = последствие + причина + как починить, одной строкой простым языком.

**Рефрейминг словаря (тех → офисно):** system prompt → «Что поручаем»; function calling/tools → «Чем разрешаем пользоваться»; memory → «Что агент помнит»; task decomposition → «Разбить на шаги»; stopping → «Когда остановиться»; guardrails/HITL → «Спросить человека перед важным действием»; critic → «Второй агент проверяет»; ReAct-трейс → «Что агент сделал»; prompt injection → «В файле спрятана вредная команда».

## Core Loop (один заход)
1. Брифинг миссии: цель + ограничения.
2. Слоты агента: `[Роль]` `[Инструменты ×N]` `[Память]` `[Планировщик]` `[Stopping criteria]` `[Guardrails/HITL]`.
3. Инвентарь деталей-карточек.
4. «Запуск» → анимированный трейс `Thought → Action → Observation`.
5. Исход + читаемый диагноз провала (отсутствует/лишняя деталь → конкретный сбой).
6. Звёздная оценка: пройдено / минимальный набор / в бюджете → ретрай или дальше.

## Прогрессия (7 уровней; офисные названия для не-айтишников; каждый Beginner→Expert)
| Ур. | Офисное название | Чему учит (тех-суть) | Пример задачи |
|-----|------------------|----------------------|---------------|
| 1 | Дай чёткое поручение | ясная инструкция/роль (system prompt) | «Составь вежливый ответ клиенту» |
| 2 | Дай доступы | инструменты: интернет/документы/калькулятор (function calling) | «Узнай курс валют на сегодня для отчёта» |
| 3 | Дай память и контекст | память: файлы, прошлый контекст | «Помни предпочтения клиента из прошлых писем» |
| 4 | Большая задача → шаги | декомпозиция, планирование | «Подготовь черновик отчёта по мероприятию» |
| 5 | Команда + проверка | мульти-агент: исполнитель + проверяющий | «Один пишет, другой проверяет факты и цифры» |
| 6 | Контроль и стоимость | бюджет, когда остановиться/вмешаться | «Останови, если рассылка >100 писем — спроси меня» |
| 7 | Безопасность (боссы) | guardrails/HITL, prompt injection | «В файле спрятана команда — не выполняй слепо» |

Между мирами — квиз-контроль из банка 271 вопрос (репо). Шаблоны репо = поздние карточки-детали.

## MVP Scope (первая версия = вертикальный срез)
**Включено (Worlds 1–3):**
- 3 мира: function calling → ReAct-петля → память. Учат неустранимое ядро (инструменты + чтение трейса) + первый «ага» (память между сессиями).
- ~12 миссий (3 мира × ~4 миссии).
- ~10–12 карточек-деталей: 3 роли, 4 инструмента (web-search, calculator, doc-reader, code-run), 3 типа памяти, stopping-criteria, 1 guardrail-тизер.
- Детерминированный движок-симулятор: покрывает эти карточки + ≥6 режимов провала.
- 1 квиз-гейт на мир (~8 вопросов, адаптированы из банка репо) ≈ 24 вопроса.
- Полный i18n RU/EN для всего MVP-контента, переключение в рантайме без перезагрузки.
- 2 режима: Кампания + Песочница (песочница ограничена MVP-картами).
- Persistence прогресса/звёзд в localStorage.

**Звёздная оценка (3 звезды/миссия):** прошёл • минимальный набор (без лишних деталей) • уложился в бюджет шагов/стоимости.

## Constraints
- Браузерная статика, без бэкенда (детерминированная симуляция → сервер не нужен).
- Стек: SvelteKit (static adapter) или React+Vite + TypeScript. Рекомендация: Svelte (легче бандл). Движок симуляции — чистый TS-модуль (тестируемый, детерминированный).
- i18n: lightweight (svelte-i18n / i18next), JSON-локали `ru.json` / `en.json`. Технические термины (ReAct, tool, prompt) — английские с RU-пояснением в тултипе.
- Hosting: статика (GitHub Pages / Netlify). Цель: 50+ одновременных подключений — тривиально для статики.
- Persistence MVP: localStorage (без аккаунтов/облака).
- Контент-источники: PDF (концепции) + репо (квизы/шаблоны/прогрессия). Соблюдать лицензию репо при реюзе.

## Non-Goals (MVP)
- Миры 4–7 (мульти-агент, продакшен, боссы-безопасность) — post-MVP.
- Real-LLM режим (настоящие вызовы модели) — post-MVP, за флагом; потребует опц. прокси.
- Multiplayer, аккаунты, облачное сохранение, лидерборды.
- Node-graph редактор (жанр B) — отклонён в пользу слот-сборки.
- Нативный мобайл (адаптивный веб — да, нативный — нет).

## Acceptance Criteria
- [ ] Игрок размещает карточки в слоты; невалидные комбинации подсвечиваются.
- [ ] «Запуск» даёт детерминированный пошаговый ReAct-трейс для (config + mission).
- [ ] ≥6 режимов провала срабатывают и дают корректный читаемый диагноз (нет web-search; нет stopping → цикл; нет guardrail → инъекция; лишняя деталь; неверная роль; превышен бюджет).
- [ ] 3 мира, ≥12 миссий проходятся от старта до конца.
- [ ] Квиз-гейт на мир, ≥70% для разблокировки следующего.
- [ ] Полное переключение RU/EN в рантайме без перезагрузки; все MVP-строки покрыты в обеих локалях.
- [ ] Прогресс и звёзды сохраняются в localStorage и восстанавливаются.
- [ ] Статичная сборка, без бэкенда; грузится и работает офлайн.
- [ ] Звёздная оценка считается по 3 критериям (пройдено / минимальный набор / в бюджете).
- [ ] На экране игрока нет кода/JSON/терминала; язык офисный; тех-термин доступен опционально за «(?)»-тултипом.
- [ ] История «что агент сделал» читается как пошаговая переписка с эмодзи-метками (🤔/🔍/👀/✅/❌).
- [ ] Диагноз провала = одна строка: последствие + причина + как починить, простым языком.

## Success Criteria (педагогические)
- Первичный: игрок проходит финальную миссию каждого мира 1–3 (собрать-запустить-пройти) без использования подсказок.
- Вторичный: квиз-гейт ≥70% на мир.
- Мастерство («blind build»): на новой миссии игрок с первой попытки выбирает минимальный правильный набор (без недо-/переоснащения) — измеряется баллом.

## Technical Context (greenfield)
Предлагаемая архитектура:
- `engine/` — чистый детерминированный ReAct-симулятор: `AgentConfig (слоты) + Mission → Trace[] + Verdict`. Юнит-тестируемый.
- `content/` — миссии, карточки, квизы как данные (JSON/TS), строки по локалям через ключи.
- `ui/` — экраны: сборка (слоты+инвентарь), запуск (анимированный трейс), результат (диагноз), карта миров, квиз.
- `i18n/` — `ru.json`, `en.json`.
